# Mini Project 과제 기준 대조와 실측 기록

2026-10-21, 제공된 `AI 서비스 Mini Project_20261020.pdf`의 10~13페이지를 기준으로 확인했습니다. 11~12페이지는 개선안 예시이며 여섯 기술을 전부 구현하라는 필수 체크리스트가 아닙니다. 10페이지는 BASE의 주제를 바꾸는 것도 허용합니다. 최종 배점은 교수자의 판단이며 아래는 구현 증거와 남은 확인 사항입니다.

## 현재 프로젝트 수준의 판단

미니 프로젝트의 개선 효과와 한계를 설명할 평가 체계는 적절한 수준으로 정립됐습니다. 이는 고정 데이터·대조 조건·지표·반복·실패 기록·재계산 방법이 갖춰졌다는 판단입니다. 모든 기능의 품질이 충분히 높거나 실사용 환경 전반이 검증됐다는 뜻은 아닙니다. 검색/충돌 검토의 오탐·미탐과 생성 품질 차이 없음도 평가 결과로 설명해야 합니다.

## 최신 기능 검증

- pytest: 105 passed. 실제 가입 엔드포인트로 로그인한 뒤 기존 주문·언어·안전·음성 모의 공급자·SSE 테스트를 수행. 새 계정 테스트는 중복·복구·이전 세션 취소·읽기/수정/삭제/내보내기의 계정 격리·시크릿 폐기·재시작 보존을 검증.
- SSE 클라이언트: `node --test tests/test_stream_client.cjs` 4개 통과. UTF-8 조각, EOF·공급자 오류, 부분 JSON 미리보기 처리 검증.
- Docker: `kharakteres:evaluation-20261021` 이미지 빌드 성공. 사용자 볼륨을 연결하지 않은 read-only + /app/data tmpfs 컨테이너에서 health·가입/로그인·저장·시크릿 폐기·fake SSE 확인. 실제 모델·음성의 컨테이너 호출이나 운영 Compose 배포를 확인한 것은 아님.
- 기존 브라우저/오디오 스모크는 계정 도입 이전 로직이 있어 이번에 재실행하지 않음. 예전 캡처를 최신 UI 전체의 검증 증거로 사용하지 않음.

## 발표에 반영할 순서

1. 문제: 생성 주문을 저장·재사용하면서 기존 세계관과의 충돌을 검토하고 싶다.
2. 개선: 구조화 주문사전, 벡터 RAG, 생성/출처/검토 그래프, 계정·시크릿·배포와 안전 처리.
3. 실측: 동일 입력의 위 수치와 대표 성공/실패를 제시. BASE 직접 비교가 아니라 기능 유무 대조임을 명시.
4. 한계: 무정답 오검색, 의미 충돌 오탐, 생성 judge 차이 없음, 문맥 토큰 증가, 언어·음성 검증 범위.
5. 다음 개선: 검색 재랭킹/거절 정책은 dev에서 조정, 다양한 미사용 test 추가, 변형/중복과 논리 모순 분리, 전문가·사용자 블라인드 평가.

인증의 이메일 기반 복구는 현재 계정 정보 일치 방식이며 이메일 소유를 토큰 링크로 검증하지 않습니다. 로컬 과제용 기능의 동작 검증과 공개 서비스용 계정 보안을 구분해 설명해야 합니다.
