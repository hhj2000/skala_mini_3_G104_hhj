# 콘텐츠 필터·벡터 주문 RAG·MCP 판단

## 구현한 기능

### 공통 콘텐츠 필터

`kharakteres/safety.py`의 `ContentGuard`를 생성 입력·출력, 언어 대화, 직접 저장/수정, 검토 입력/출력, STT 결과, TTS 입력, 검색 질의에 연결했습니다.

기본 검사 모델은 OpenAI의 기존 fast 모델, Ollama의 기존 quality 모델입니다. 작은 `qwen3:0.6b`의 혐오 문맥 누락을 실제 확인해 Ollama는 quality 모델로 선택했습니다.

1. Unicode NFKC·제로폭 문자 정리와 알려진 욕설·혐오·현실 정치 표현 검사.
2. 실제 실행 기본값 `CONTENT_FILTER_MODE=model`: 설정된 검사 LLM에 별도 콘텐츠 분류 프롬프트와 판정 JSON 스키마를 전달.
3. 욕설/모욕, 집단 혐오, 현실 정치 발언을 차단. 허구 정치·판타지 전투·무해한 일반 언급은 허용하도록 지시.
4. 차단은 422와 `content_blocked`/분류/단계로 반환. 모델 검사 오류·25초 초과·일관되지 않은 판정은 503으로 중단. unsafe 원문·공급자 오류·키를 사용자 오류 메시지에 인용하지 않음.
5. 같은 콘텐츠 판정은 최대 128개·5분 캐시. LangSmith `safety.content_check`로 추적.

이는 서비스 정책 분류기이며 모든 언어와 우회·문맥의 탐지를 보장하지 않습니다. fake/rules 모드에는 문맥 분류가 없으므로 실제 model 모드와 구분합니다. 기존 개인 DB를 자동 삭제하지 않으며, 알려진 차단 표현이 있는 기존 기록은 RAG 후보에서 제외합니다. 원본 API 입력은 기존 LangSmith 추적 정책에 따라 기록될 수 있습니다.

### 로컬 벡터 주문 RAG

`kharakteres/retrieval.py`는 FastEmbed의 다국어 ONNX 모델(`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, 384차원)을 사용합니다.

`주문 DB → 내용·모델 지문 → 변경 문서 임베딩 → 별도 SQLite 벡터 캐시 → 요청 임베딩 → 세계관/필터 범위 내 NumPy 코사인 유사도 → 상위 후보 → 생성 프롬프트`

- 문서에는 이름·원문·효과·의미·제약·메모·세계관·언어·속성·계열·태그를 포함합니다.
- 생성 시 같은 세계관의 관련 주문 최대 12개. 목록 의미 검색은 필터 적용 후 최대 30개.
- `SPELL_RAG_MIN_SCORE=0.25` 기본 임계값. 생성 프롬프트에는 기존처럼 후보 이름·원문·효과·속성을 제공하며 모든 제약의 일관성을 보장하지는 않습니다.
- 수정된 문서는 재임베딩, 삭제된 주문 벡터는 다음 조회에서 제거. 모델을 바꾸면 지문이 달라져 재계산합니다.
- 인덱스 기본 경로는 `SPELL_DB_PATH` 뒤에 `.vectors.sqlite`를 붙인 별도 파일입니다. Git에서 제외됩니다. 모델은 FastEmbed 캐시에 보관하며 개인 주문 내용은 외부 임베딩 API에 전송하지 않습니다.
- 빈 서고에서는 모델을 로드하지 않습니다. 모델 준비 지연·오류·동시 준비 중에는 응답을 무한 대기시키지 않고 대체 조회와 이유를 표시합니다. 진행 중인 모델 작업을 중복으로 만들지 않으며 오류 후 60초 재시도 대기를 둡니다.
- `SPELL_VECTOR_ENABLED=0`이면 생성은 기본 조회, 목록 의미 검색은 키워드로 대체. fake는 기본 0, 실제 모드는 기본 1입니다.
- Wiktionary 조회는 생성 후 어휘 출처 확인입니다. 외부 문헌을 바탕으로 문장을 재생성하거나 문법·발음을 인증하는 RAG로 표시하지 않습니다.

## 도입하지 않은 기능과 이유

### Multi-Agent

현재 단계가 분명하고 별도의 AI 설정 검토가 이미 있습니다. 독립 에이전트에게 도구 선택·상호 메시지·재계획을 맡길 명확한 필요가 적고 호출 수·지연·오류 가능성이 증가합니다. 이번에는 LangGraph 워크플로를 유지했습니다. 함수 역할 분리나 서로 다른 음성 모델 호출을 멀티 에이전트라고 부르지 않습니다.

향후 외부 언어 자료 조사·후보 작성·독립 검수 결과의 협상을 제품 요구로 채택한다면 별도 에이전트 상태·도구·종료 조건과 평가를 갖춘 구조를 검토할 수 있습니다. 현재 구현된 것으로 발표하지 않습니다.

### MCP

현재 Kharakteres 실행 경로에는 MCP 연결이 없습니다. FastAPI가 로컬 주문/임베딩 모듈을 호출하고 Wiktionary·음성 API에는 HTTP 요청합니다.

보존된 장애 진단 Base는 `SERVICE_MODE=incident`일 때 `agent/mcp_client.py`에서 stdio 자식 프로세스와 MCP 세션을 열어 다음을 사용합니다.

| 서버 | 사용 목적 |
|---|---|
| `mcp_server.py` (`ops`) | `get_monitoring_status`, `search_runbooks`, Runbook 리소스와 프롬프트 |
| `mcp_server_docs.py` (`docs`) | 서비스 문서 리소스 템플릿 탐색 및 읽기 |

Base에서 MCP는 도구·문서 제공자와 실행 그래프의 인터페이스를 분리하고 한 번 만든 연결을 재사용하는 역할입니다. Kharakteres의 현재 단일 서비스에는 추가 MCP 프로세스를 도입할 이익이 작고 기동·연결 실패 지점이 늘어 도입하지 않았습니다.

## 검증

자동 테스트 94개, 기존 CRUD·재시작·음성 UI 회귀 검증을 통과했습니다. 실제 ONNX 의미 검색·세계관 필터·콘텐츠 차단 UI는 `eval/kharakteres_safety_rag_browser.py`로 검증했습니다.

- 네트워크 없는 회귀: `tests/test_safety_rag.py`. 알려진 우회 표기, 정상 판타지 허용, 직접 저장/TTS 우회 차단, STT/생성 결과 차단, 모델 오류 시 중단, 캐시 지속·수정·삭제·세계관 분리 확인.
- 실제 모델: `eval/kharakteres_rag_live.py`. 테스트용 임베더와 별개로 실제 ONNX 의미 순위와 설정된 검사 LLM의 문맥 판정, 벡터 맥락을 이용한 생성 확인.
- 결과: `eval/results/kharakteres-safety-rag-live.json`. API 비용이 드는 실제 검증은 별도로 실행합니다.

## SSE 생성 경로

현재 웹 화면은 SSE 생성 경로를 사용합니다. 입력 검사와 최종 콘텐츠 검사는 유지하며, 작성 중 응답에는 누적 규칙 검사를 적용합니다. 완성 전 토큰 미리보기는 전체 문맥 검사가 끝난 결과와 구분합니다. 실패·차단 시 초안을 지우고 저장을 막습니다. 자세한 범위는 [SSE 안내](STREAMING.md)에 기록했습니다.
